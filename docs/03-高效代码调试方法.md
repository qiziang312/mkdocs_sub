# 高效代码调试方法

## 前言

调试是开发过程中耗时最多的环节之一。掌握系统化的调试方法，比盲目地 `print` 和猜测要高效得多。本文档涵盖了调试的核心思路和针对不同语言/场景的实用技巧。

---

## 1. 调试思维框架

### 科学调试法

```
观察现象 → 提出假设 → 设计验证 → 执行测试 → 分析结果 → 修复代码
    ↑                                                       │
    └───────────────────────────────────────────────────────┘
                      （如果假设被推翻，重新循环）
```

### 关键原则

1. **复现是第一步**：无法稳定复现的 Bug 几乎不可能修复
2. **一次只改一个变量**：同时修改多处会让你无法判断哪一步是有效的
3. **橡皮鸭调试法**：向一个物体（或同事）逐行解释你的代码，往往在解释过程中自己就能发现问题
4. **记录你的尝试**：把试过的方法和结果记下来，避免重复走弯路
5. **缩小问题范围**：用二分法定位问题发生的精确位置

## 2. 调试手段层级（从简到深）

```
Level 1: print / console.log           ← 快速但不优雅
Level 2: 断言 (assert)                 ← 自动检测假设
Level 3: 日志 (logging)                ← 持久化、可分级的记录
Level 4: 交互式调试器 (debugger)       ← 断点、单步执行、变量检查
Level 5: 性能分析器 (profiler)         ← 时间/内存瓶颈诊断
Level 6: 内存调试 (valgrind/heap dump) ← 内存泄漏和越界
```

> **建议**：日常开发以 Level 3-4 为主，Level 2 作为辅助，Level 1 仅用于快速验证。

## 3. Print 调试的正确姿势

不是说 `print` 不好，而是要用得聪明：

```python
# ❌ 低效的 print —— 看了也不知道在哪叫的
print("got here")
print(value)

# ✅ 高效的 print —— 包含上下文信息
print(f"[{__file__}:{sys._getframe().f_lineno}] value={value!r}, type={type(value).__name__}")
```

### 使用 `icecream` 库（Python）

```python
from icecream import ic

# 自动输出变量名和值，无需手动写 f-string
user = {"name": "Alice", "age": 25}
ic(user)  # ic| user: {'name': 'Alice', 'age': 25}

# 调试函数调用
ic(user.get("email", "not found"))
```

## 4. 使用调试器（Debugger）

### 4.1 Python — `pdb` / `ipdb`

```python
# 在代码中插入断点
import pdb; pdb.set_trace()  # 或 Python 3.7+ 直接用 breakpoint()

def process_order(order_id):
    items = fetch_items(order_id)
    breakpoint()  # ← 程序在此暂停，进入交互式调试
    total = sum(item.price for item in items)
    return total
```

常用 `pdb` 命令：

| 命令 | 作用 |
|------|------|
| `n` (next) | 执行下一行 |
| `s` (step) | 进入函数内部 |
| `c` (continue) | 继续执行到下一个断点 |
| `l` (list) | 显示当前代码上下文 |
| `p <var>` | 打印变量值 |
| `pp <var>` | 美化打印 |
| `w` (where) | 显示调用栈 |
| `u` / `d` | 在调用栈中上下移动 |
| `q` (quit) | 退出调试 |

### 4.2 JavaScript/Node.js — Chrome DevTools & Node Inspector

```javascript
// 在代码中设置断点
debugger;  // DevTools 打开时会在此暂停

// 使用浏览器断点类型
// - 行断点 (Line-of-code)
// - 条件断点 (Conditional breakpoint)
// - DOM 断点 (DOM change breakpoint)
// - XHR/Fetch 断点
// - Event Listener 断点
```

**Node.js 调试**：

## 5. 常见 Bug 模式与排查策略

### 5.1 空值与未定义

```python
# ❌ 常见错误
user = find_user(id)
print(user.name)  # AttributeError: 'NoneType' object has no attribute 'name'

# ✅ 防御式编程
user = find_user(id)
if user is None:
    raise ValueError(f"User {id} not found")
print(user.name)
```

### 5.2 可变默认参数陷阱（Python）

```python
# ❌ 这是个经典陷阱
def add_item(item, items=[]):  # 默认参数在函数定义时只创建一次！
    items.append(item)
    return items

add_item(1)  # [1]
add_item(2)  # [1, 2] ← 不是 [2]！

# ✅ 正确做法
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

### 5.3 异步代码调试

```javascript
// ❌ Promise 未处理的拒绝
async function fetchData() {
    const response = await fetch('/api/data');  // 网络错误时无 catch
    return response.json();
}

// ✅ 始终处理错误
async function fetchData() {
    try {
        const response = await fetch('/api/data');
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        return await response.json();
    } catch (error) {
        console.error('Failed to fetch data:', error);
        throw error;  // 重新抛出让调用方处理
    }
}
```

### 5.4 浮点数精度问题

```python
# ❌ 不要直接比较浮点数
0.1 + 0.2 == 0.3  # False！

# ✅ 使用容差比较
import math
math.isclose(0.1 + 0.2, 0.3)  # True
```

## 6. 结构化日志（Logging）

### 配置示例（Python）

```python
import logging

# 配置日志格式和级别
logging.basicConfig(
    level=logging.DEBUG,
    format='%(asctime)s [%(levelname)s] %(name)s:%(lineno)d - %(message)s',
    handlers=[
        logging.FileHandler('app.log'),
        logging.StreamHandler()
    ]
)

logger = logging.getLogger(__name__)

# 使用不同级别
logger.debug("详细的调试信息，生产环境通常关闭")
logger.info("一般信息，如"用户登录成功"")
logger.warning("警告，如"磁盘空间不足"")
logger.error("错误，如"数据库连接失败"")
logger.critical("严重错误，如"系统即将崩溃"")
```

### 日志级别选择指南

| 级别 | 用途 |
|------|------|
| `DEBUG` | 开发调试，包含变量值、函数调用详情 |
| `INFO` | 关键业务流程节点 |
| `WARNING` | 非预期但可恢复的情况 |
| `ERROR` | 需要人工介入的错误 |
| `CRITICAL` | 影响系统整体运行的严重问题 |

## 7. 性能调试入门

### 7.1 定位瓶颈

```python
# Python — 使用 cProfile
python -m cProfile -s cumulative my_script.py

# 或使用 timeit 测量小段代码
python -m timeit -s "from my_module import my_func" "my_func(100)"
```

```bash
# Linux — 使用 time 命令快速评估
time python my_script.py
# real    0m2.341s   ← 实际运行时间
# user    0m2.156s   ← CPU 用户态时间
# sys     0m0.047s   ← CPU 内核态时间
```

### 7.2 常见性能陷阱

- **N+1 查询**：循环内执行数据库查询
- **不合理的循环嵌套**：O(n²) 本是可用 O(n) 解决的
- **未使用缓存**：重复计算相同结果
- **过度同步**：不必要的锁竞争
- **大对象拷贝**：传递引用优于拷贝数据

## 8. 调试清单（Checklist）

遇到 Bug 时，按以下顺序排查：

- [ ] 错误信息和堆栈跟踪读仔细了吗？
- [ ] 问题能稳定复现吗？
- [ ] 最小化复现步骤（去掉无关代码）了吗？
- [ ] 相关的输入是什么？边界值测试了吗？
- [ ] 最近改了什么？（`git diff` / `git log`）
- [ ] 日志中有什么异常信息？
- [ ] 依赖的版本对得上吗？
- [ ] 环境变量和配置文件正确吗？
- [ ] 同样的代码在别的环境能跑吗？

---

## 结语

调试是一门手艺，需要刻意练习。记住：**最好的调试是不需要调试** —— 花时间写清晰的代码、充分的测试和良好的日志，能在很大程度上减少调试的需求。当 Bug 真的找上门时，冷静、系统化、有条理地排查，远比焦躁地随机尝试有效。
